# License Recommendation

Date: 2026-07-25; decision recorded 2026-08-12
Scope: LumenFin and FinAgentBench
Status: **MIT selected for project-owned source in both repositories**

## Recommendation

The owner selected **MIT** for both repositories, with copyright
`2026 Jiali Ma`. `LICENSE` files and package metadata now record that choice.

This decision covers project-owned source only. It does not authorize
redistribution of LumenFin's current application image as a purely MIT
artifact: PyMuPDF is AGPL-3.0/commercial, MinIO is AGPL-3.0, and Redis 7.4 is
RSALv2/SSPLv1. Filing-fixture and external-data rights also remain separate.

## Options

| Option | Benefits | Constraints | Fit |
|--------|----------|-------------|-----|
| MIT | Short, familiar, portfolio-friendly; permits commercial and private reuse; same license can cover both repositories | Requires preservation of copyright/license notice; no explicit patent grant; does not override dependency or fixture licenses | **High** for both projects |
| Apache-2.0 | Permissive plus explicit patent license and patent-termination terms; NOTICE mechanism supports larger ecosystems | Longer obligations; modified files/NOTICE handling; still does not make AGPL dependencies permissive | Medium–High |
| No public grant | Maximum control; avoids accidentally granting reuse before provenance review | Public GitHub users have no permission to copy, modify or redistribute beyond platform terms; poor fit for a reusable portfolio tool | Medium as a temporary release hold, Low as final tool positioning |

## Direct dependency review

Installed metadata was checked for LumenFin's direct runtime dependencies.

| Dependency | Reported license | Release implication |
|------------|------------------|---------------------|
| LangGraph, FastAPI, SQLAlchemy, redis-py, OpenPyXL, Pydantic, MCP SDK | MIT | Compatible with MIT/Apache distribution with notices |
| NetworkX, Uvicorn, HTTPX, python-dotenv | BSD-3-Clause | Preserve notices |
| RQ | BSD-2-Clause | Preserve notice |
| python-multipart, milvus-lite | Apache-2.0 | Preserve license/notice |
| yfinance | Apache metadata | Code license is permissive, but Yahoo data/service terms remain separate |
| psycopg / psycopg-binary | LGPL-3.0-only | Dynamic/library use is generally compatible, but redistribution obligations and notices must be observed |
| **PyMuPDF** | **AGPL-3.0 or commercial** | **High-risk blocker for distributing a Docker image or combined application under only MIT; obtain commercial terms, comply with AGPL, or replace it** |
| PyMilvus | Apache-2.0 (upstream verified) | Preserve upstream license/notice |

FinAgentBench declares no runtime dependencies, so its own license decision is
comparatively straightforward.

## Source provenance

- No copied-code copyright/SPDX headers were found in project source scans.
- This is not proof of authorship; commit history and any manually copied
  snippets still require owner confirmation.
- Generated EvalReports and synthetic mutation fixtures can be licensed with
  the project if they were authored for this repository.

## Fixture and data rights

- `fixtures/e2e_real/*.htm` and PDFs are derived from issuer SEC filings.
  Public SEC access does not by itself establish that every issuer filing,
  logo, chart or transformed PDF can be redistributed under MIT.
- Synthetic stress PDFs generated by repository scripts are lower risk, subject
  to confirming all embedded text/fonts/assets are project-owned.
- Yahoo/market outputs must not be committed or redistributed merely because
  the client library is permissively licensed.

Until reviewed, real-filing fixtures should remain **uncertain: do not stage,
delete or license**.

## Same-license decision

Using MIT for both repositories simplifies the paired RC story and downstream
integration. Keep third-party notices separate per repository. The benchmark
can be licensed independently before LumenFin if desired.
